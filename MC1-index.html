Engineering AI‑Assisted Tagging at Scale

Designing reliable tagging workflows across review sets of up to 5 million documents.

Ethan CoskayRole: Software Engineer InternStack: C# · .NET · Cosmos DB · distributed caching

The 30-second version

Problem
One reviewer decision has to apply correctly to every duplicate and related document, across millions of items.
What I built
Duplicate-aware tag propagation, a safe fallback for missing data, and AI-assisted tag recommendations, shipped behind feature flags.
Result
An estimated 1,500+ hours of manual tagging saved for users.

Simplified conceptual visualization. No proprietary Microsoft code, customer data, internal architecture, or confidential implementation details are shown. All diagrams are my own.

The problem

One decision, many documents

Review sets hold large collections of documents. Many are exact duplicates, and many belong to families, like an email and its attachments. When a reviewer tags one document, that decision has to reach every related copy, or the review ends up inconsistent.

Scale

Applying a tag is easy. Keeping it correct at 5 million documents is the hard part.

With ten documents, a mistake is visible and cheap to fix. At production scale, a small inconsistency repeats across thousands of duplicate groups, and nobody can check them by eye. Correctness has to be designed into the system.

    Engineering decisions

    Four decisions that shaped the system

    Expand relationships before tagging

    Problem
    A reviewer selects one item, but that item can stand for a whole document family.
    Decision
    Expand every selected ID into its members before any tag is written.
    Why it mattered
    Families are tagged as a unit, so related documents never drift apart.

    Treat IDs case-insensitively

    Problem
    The same document can arrive with identifiers that differ only in letter case.
    Decision
    Merge ID sets case-insensitively before propagation.
    Why it mattered
    No document is tagged twice or skipped because of formatting.

    Fail predictably, not loudly

    Problem
    Duplicate data can be missing or incomplete when a tag is applied.
    Decision
    Define a deterministic fallback path instead of letting the request error out.
    Why it mattered
    The reviewer's decision still completes, and downstream pipelines don't fail.

    Ship behind feature flags

    Problem
    A change to tagging behavior affects live reviews immediately.
    Decision
    Gate the feature with flighting so it can be turned on gradually.
    Why it mattered
    Controlled rollout, and rollback without downtime if something looks wrong.

    Reliability

    What if the data isn't there?

    Switch the input and compare the two paths.

    Reliable systems are designed for imperfect inputs.

    AI-assisted recommendations

    From one document to a suggested tag

    Propagation handles copies. Recommendations help with documents that are similar but not identical, by suggesting tags that related content already carries.

    ＋ Engineering detail: keeping it fast at scale
    • I integrated an embedding service and similarity orchestration into the tagging workflow.
    • The pipeline is backed by Cosmos DB, with cache-based embedding reuse so a document's vector doesn't have to be recomputed each time it is needed.
    • Computing embeddings is the expensive step, so reuse is what keeps recommendations practical across review sets of millions of documents.

      Think in systems
